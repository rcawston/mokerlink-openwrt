net: ethernet: realtek: rtl9300: set the switch up for standalone ports

Before there are any ports, the switch has to be set up so that each
port is an interface of its own: every frame a port receives goes to
the CPU, and nothing is forwarded between two ports in hardware. Where
the boot loader may have left something else, it is overwritten.

- The port isolation table lets each front port forward only to the
  CPU port, and the CPU port to all of them.
- Every port forwards in MSTI 0, the spanning tree instance of all
  VLANs.
- No port learns source addresses, so every frame is flooded, and the
  isolation limits the flood of a port to the CPU. Frames from new
  source addresses, and frames past the learning limit, are forwarded.
  Entries the boot loader learned are removed.
- Every port is a member of every VLAN, without ingress or egress
  filtering. 0x8100 is the only TPID taken for a tag, and VID 0, which
  untagged frames get, is the only one sent untagged, so frames keep
  their tags, apart from priority tags, which are probably lost, and
  VLANs neither restrict nor change what reaches the CPU.
  Unlike OpenWrt, no port takes 0x88a8 for an outer tag, so S-tagged
  frames pass with their tags in the payload.
- Link-local frames (01-80-c2-00-00-xx) are trapped to the CPU.
- The MACs stay off until a port has a link.

The registers and their encoding follow OpenWrt's realtek target
(drivers/net/dsa/rtl83xx and drivers/soc/realtek/otto_table.c there).
