net: pse-pd: don't drop a classification reported with a detection

pse_set_config_isr() returns right away when the notifications have
PSE_BUDGET_EVAL_STRAT_DYNAMIC set. That is a budget evaluation
strategy, not an event, and its value is that of
ETHTOOL_C33_PSE_EVENT_DETECTION. The TPS23881 reports the detection
and the classification of a PI in one notification when it reads both
events together, and the classification is then dropped: with
software power control, isr_pd_detected stays false, so the PD is
powered neither then nor by a later admin enable.

pse_set_config_isr() is only called for the power domains with
software power control, which pse_pw_d_is_sw_pw_control() never
reports for the dynamic strategy, so the check does nothing about the
strategy. It wasn't meant to drop detections either: the check right
after it, for a connection and a disconnection reported together,
tests for a detection. Remove it.

A detection reported together with a disconnection now reaches that
check and is reported as an error, as a classification with a
disconnection already is. Both were dropped before, and still are.

This was found by Sashiko, the netdev AI review bot, in its review of
"net: pse-pd: don't enable a PI again while disabling it" (the Link
below), not on hardware. Build-tested only: I don't have a TPS23881,
and the Realtek RTL8239 PSE controllers I use never report a detection
together with another event, so nothing changes for them.
